# Downstream Firefox patch inventory

This is the durable inventory of changes to existing Firefox files on the
`naivefox-full-source` reference branch. It contains stable patch identifiers and semantic
review obligations, not mutable branch SHAs or dated test results. Git history
is the authority for the exact diff and originating commit.

During every Firefox refresh, inspect every listed file and invariant even when
Git reports no textual conflict. Remove an entry when the downstream change is
removed or replaced by an upstream-supported equivalent.

## NF-UPSTREAM-001: register the NaiveFox build

Files:

```text
netwerk/moz.build
```

Registers `netwerk/naivefox/` in the Firefox build traversal. Normal Firefox
directory selection and runtime behavior remain unchanged. Review the parent
manifest and prove that the NaiveFox target is generated by the intended
product configuration.

## NF-UPSTREAM-002: marker-free raw proxy CONNECT

Files:

```text
netwerk/protocol/http/nsIHttpChannelInternal.idl
netwerk/protocol/http/HttpBaseChannel.cpp
netwerk/protocol/http/nsHttpChannel.cpp
netwerk/protocol/http/nsHttpConnection.cpp
netwerk/test/unit/test_proxyconnect_raw.js
netwerk/test/unit/xpcshell.toml
```

Allows an empty `HTTPUpgrade()` protocol only on a connect-only channel so a
successful proxy CONNECT exposes async streams without emitting synthetic
`ALPN`, `Upgrade`, or `Connection` headers. It also preserves the connect-only
transaction while a first-use HTTPS proxy completes its H2 restart.

Review obligations: non-empty upgrade behavior stays unchanged, every
connect-only channel still requires a callback, the empty value cannot be used
by ordinary channels, and the focused raw/proxy CONNECT tests inspect the wire
headers.

## NF-UPSTREAM-003: validated proxy CONNECT headers

Files:

```text
netwerk/protocol/http/nsIHttpChannelInternal.idl
netwerk/protocol/http/HttpBaseChannel.h
netwerk/protocol/http/HttpBaseChannel.cpp
netwerk/protocol/http/nsHttpRequestHead.h
netwerk/protocol/http/nsHttpRequestHead.cpp
netwerk/protocol/http/PHttpChannelParams.h
netwerk/protocol/http/nsHttpConnection.cpp
netwerk/test/unit/test_proxyconnect_padding_header.js
netwerk/test/unit/xpcshell.toml
```

Adds a privileged pre-open sidecar for headers copied only into the generated
proxy CONNECT request. NaiveFox uses it for `padding`; it does not add that
header to an origin request.

Review obligations: copy/move and IPC serialization preserve the sidecar;
authority, framing, hop-by-hop, authentication, ALPN, invalid token, and invalid
value inputs remain rejected; H1 and H2 CONNECT tests verify the request and
response metadata paths.

## NF-UPSTREAM-004: export the NaiveFox entry point

Files:

```text
toolkit/library/libxul.symbols
```

Exports the single C ABI bootstrap entry used by the dependent executable while
the Gecko-facing implementation remains inside `libxul` with internal Necko,
PSM, preference, and shutdown APIs.

Review obligations: the symbol remains otherwise isolated and the dependent
executable passes runtime startup, shutdown, and HTTPS sanity checks.

## NF-UPSTREAM-005: H2 raw-tunnel byte-stream lifecycle

Files:

```text
netwerk/protocol/http/Http2Session.cpp
netwerk/protocol/http/Http2StreamTunnel.cpp
netwerk/protocol/http/Http2StreamTunnel.h
```

Makes raw H2 tunnels report bytes consumed for flow-control accounting, maps a
successful output close to send-side `END_STREAM`, and delivers buffered bytes
before graceful EOF after peer `RST_STREAM(NO_ERROR)`.

Review obligations: tunnel callbacks never consume more than requested,
ordinary HTTP transactions and failed resets retain their behavior, buffering
stays bounded, and large transfer, slow consumer/producer, half-close, reset,
and concurrent-stream regressions pass.

## NF-UPSTREAM-006: strict H3 proxy selection

Review obligations: the flag survives clone and IPC serialization, strict H3

## NF-UPSTREAM-007: reentrant-safe H3 tunnel callbacks

Files:

```text
netwerk/protocol/http/Http3StreamTunnel.cpp
netwerk/test/http3server/src/main.rs
netwerk/test/unit/test_proxyconnect_h3_raw.js
netwerk/test/unit/xpcshell.toml
```

Publishes raw H3 tunnel async callbacks before notifying the session because
notification may synchronously re-enter stream processing. A callback consumed
by reentrancy must not be restored afterward.

Review obligations: ordinary H3 waits remain unchanged, the focused classic
CONNECT test obtains both streams, verifies `padding`, and rejects synthetic
upgrade markers.

## NF-UPSTREAM-008: H3 classic-CONNECT half-close

Files:

```text
netwerk/protocol/http/Http3StreamTunnel.cpp
netwerk/protocol/http/Http3StreamTunnel.h
third_party/rust/neqo-http3/src/connection.rs
third_party/rust/neqo-http3/.cargo-checksum.json
netwerk/test/unit/test_proxyconnect_h3_raw.js
```

Maps successful output close for a connect-only classic CONNECT to Neqo's
send-side FIN while retaining the response handler. Failed close still cancels
the full stream; WebTransport and CONNECT-UDP keep coupled lifecycle semantics.

Review obligations: the vendored checksum matches, scope remains
`NS_HTTP_CONNECT_ONLY`, and response-after-request-FIN regressions pass.

## NF-UPSTREAM-009: bounded H3 receive lifecycle

Files:

```text
netwerk/protocol/http/Http3Session.cpp
netwerk/protocol/http/Http3StreamTunnel.cpp
netwerk/protocol/http/Http3StreamTunnel.h
netwerk/test/unit/test_proxyconnect_h3_raw.js
```

Caps connect-only H3 slow-consumer buffering at 256 KiB, reports buffered bytes
through `Available()`, retains received FIN until buffered data is drained, and
treats tunnel `STOP_SENDING` as a send-direction event rather than discarding
the receive side.

Review obligations: scope remains classic connect-only tunnels; ordinary H3,
WebTransport, CONNECT-UDP, and non-tunnel reset handling are unchanged; slow
drain, large integrity, bounded memory, proxy loss, and concurrent-stream tests
pass.

## Adding or removing an entry

Use the next stable identifier and record:

- exact existing Firefox files and focused tests;
- why project-only code or an existing API is insufficient;
- the narrow behavior change and unaffected default behavior;
- the refresh invariants and acceptance tests.

Do not add branch-tip SHAs, dates, benchmark numbers, or run transcripts. When a
patch is removed, delete its entry in the same shared change and let Git history
preserve the former rationale.
